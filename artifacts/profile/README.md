# Профиль горячих путей

Три одинаковых Criterion-сценария (`fib_32`, `dedup_10k`, `normalize_65k`) профилировались по 5 секунд каждый с частотой 997 Гц внутри одного perf-сеанса. Сборка выполнялась с debug symbols в профиле `bench`.

- до: commit `5bba92d`, 14976 samples;
- после: commit `92ab711`, 15029 samples;
- потерянных samples: 0 в обоих запусках.

## Узкие места до

- `slow_fib`: 33,18% циклов — экспоненциальная рекурсия;
- `slow_dedup`: 16,99% — вложенный линейный поиск дубликатов;
- `core::slice::sort::unstable::ipnsort`: 16,29% — сортировка после каждой вставки;
- `normalize` и связанные копирования: 33,00% — две последовательно создаваемые строки.

## Узкие места после

- `fast_fib`: 31,24% циклов выделенного ему интервала;
- `HashMap::insert`, используемый `HashSet`: 30,48%;
- `normalize`: 32,08%, ещё 1,76% занимает `str::to_lowercase`;
- остальная часть `fast_dedup`: 2,24%.

Профиль подтверждает устранение рекурсивного Fibonacci, повторных линейных проходов и сортировок. Каждый benchmark намеренно выполнялся одинаковое время, поэтому доли показывают внутреннюю структуру выделенных интервалов, а абсолютное ускорение приведено в Criterion-отчёте.

Файлы:

- `flamegraph-before.png`;
- `flamegraph-after.png`;
- `perf-before.txt` и `perf-after.txt`.

Профиль `before` восстановлен непосредственно из сохранённого commit `5bba92d` в изолированной копии репозитория; исходная рабочая ветка не изменялась.
